# AI-журнал для Лабораторной №4

## 1. Задача

Разработать прототип CLI-интерфейса для системы учёта заявок, включающий не менее 5 экранов (вход, список, создание, карточка, редактирование, удаление), с учётом UX-требований.

## 2. Использованная модель

## GPT-4 (OpenAI)

## 3. Промпт (что я отправил ИИ)
>
> «Составь подробный UX-чек-лист для системы учёта заявок с CLI-интерфейсом. Включи пункты по навигации, формам, ошибкам, пустым состояниям, фильтрации, доступности и понятности статусов. Для каждого пункта дай критерий оценки "хорошо/плохо" и пример реализации в CLI.»

## 4. Почему такой промпт

Мне нужны были конкретные критерии для оценки интерфейса, а не общие слова. Формат «хорошо/плохо» помогает быстро проверить свой прототип и найти слабые места.

## 5. Почему выбрана эта модель

GPT-4 хорошо знает принципы UX-дизайна и может дать структурированный чек-лист с примерами, применимыми к консольному интерфейсу.

## 6. Результат от ИИ

ИИ предоставил чек-лист из 11 критериев по 6 категориям:

- Навигация (2 пункта)
- Формы (2 пункта)
- Ошибки (2 пункта)
- Пустые состояния (1 пункт)
- Фильтрация (1 пункт)
- Доступность (1 пункт)
- Статусы (2 пункта)

## 7. Проверка результата

Я проверил каждый критерий на применимость к CLI-интерфейсу. Все критерии подходят: в CLI есть меню, формы ввода, обработка ошибок, фильтры через аргументы командной строки.

## 8. Собственная доработка

По результатам оценки ИИ я:

- Добавил live-валидацию полей (подсветка при ошибке)

- Добавил легенду статусов внизу списка
- Добавил команду смены пароля
- Добавил сортировку по дате
- Добавил сообщение для пустого состояния

## 9. Вывод

ИИ помог выявить 6 улучшений, все из них были учтены при доработке прототипа. Работа с нейросетью позволила сделать интерфейс более дружелюбным и соответствующим UX-стандартам.
