# Техническое задание: Система учёта заявок Helpdesk

## 1. Назначение системы

Система предназначена для автоматизации процесса обработки заявок в учебном заведении, сокращения времени на их обработку и повышения прозрачности всех процессов.

---

## 2. Роли пользователей

| Роль | Права |
| ---- | ----- |
| **Администратор** | Управление пользователями, настройка справочников, просмотр статистики, управление ролями |
| **Оператор** | Создание заявок, назначение исполнителей, изменение статусов, фильтрация заявок |
| **Исполнитель** | Просмотр назначенных заявок, изменение статуса выполнения, добавление комментариев |
| **Заявитель** | Создание заявок, просмотр статусов, добавление комментариев, поиск по своим заявкам |

---

## 3. Функциональные требования

| ID | Требование | Приоритет |
| -- | ---------- | --------- |
| FR-01 | Система должна позволять заявителю создавать заявку с выбором категории | Высокий |
| FR-02 | Система должна позволять оператору назначать исполнителя | Высокий |
| FR-03 | Система должна отображать статус заявки в реальном времени | Высокий |
| FR-04 | Система должна поддерживать фильтрацию заявок по статусу, категории, дате | Средний |
| FR-05 | Система должна отправлять уведомления при смене статуса (email + push) | Средний |
| FR-06 | Система должна позволять добавлять комментарии к заявке | Средний |
| FR-07 | Система должна вести историю изменений по каждой заявке (аудит) | Высокий |
| FR-08 | Администратор должен иметь возможность управлять категориями заявок | Средний |
| FR-09 | Система должна экспортировать отчеты в Excel | Низкий |
| FR-10 | Система должна поддерживать поиск по ключевым словам | Средний |
| FR-11 | Система должна поддерживать мобильную версию (адаптивный интерфейс) | Средний |
| FR-12 | Система должна поддерживать интеграцию с Active Directory | Низкий |
| FR-13 | Система должна генерировать ежедневные/еженедельные отчёты по заявкам | Низкий |
| FR-14 | Система должна поддерживать SLA (сроки обработки заявок) | Средний |

---

## 4. Жизненный цикл заявки

| Статус | Описание | Кто может изменить |
| ------ | -------- | ------------------ |
| **Новая** | Заявка создана заявителем | Заявитель, Оператор |
| **Назначена** | Оператор назначил исполнителя | Оператор |
| **В работе** | Исполнитель начал работу | Исполнитель |
| **Выполнена** | Исполнитель завершил работу | Исполнитель |
| **Закрыта** | Заявка закрыта, подтверждена | Оператор, Администратор |

## 5. Нефункциональные требования

| ID | Требование | Описание |
| -- | ---------- | -------- |
| NFR-01 | Безопасность | Пароли должны храниться в хешированном виде (bcrypt) |
| NFR-02 | Производительность | Время отклика системы не более 2 секунд (95% запросов) |
| NFR-03 | Надёжность | Система должна работать без сбоев 99% времени (SLA 99%) |
| NFR-04 | Удобство | Интерфейс должен быть понятен пользователю без обучения (UX-тесты) |
| NFR-05 | Масштабируемость | Система должна поддерживать до 1000 одновременных пользователей |
| NFR-06 | Интеграция | Система должна интегрироваться с почтовым сервером (SMTP) |
| NFR-07 | Доступность | Система должна быть доступна с мобильных устройств (adaptive) |

## 6. Use Case диаграмма

![alt text](<Диаграмма без названия.drawio.png>)

- **Заявитель:** Создать заявку, Просмотреть статус, Добавить комментарий, Поиск по своим заявкам
- **Оператор:** Распределить заявку, Изменить статус, Фильтровать заявки, Управлять SLA
- **Исполнитель:** Выполнить заявку, Закрыть заявку, Добавить комментарий, Изменить статус
- **Администратор:** Управлять ролями, Управлять категориями, Просматривать отчёты, Настраивать систему

## 7. Критерии приемки

- [ ] Создана заявка с заполнением всех полей (категория, описание, приоритет)
- [ ] Назначен исполнитель (автоматически/вручную)
- [ ] Изменён статус (все переходы работают корректно)
- [ ] Добавлен комментарий (виден всем участникам)
- [ ] Экспортирован отчёт (Excel, PDF)
- [ ] Уведомления отправлены при смене статуса (email + push)
- [ ] История изменений сохраняется (аудит-лог)
- [ ] Фильтрация работает (по статусу, категории, дате)
- [ ] Поиск работает (по ключевым словам, ID заявки)
- [ ] SLA соблюдается (время реакции < 24 часа)

## 8. Дополнительные требования (из генерации)

### Улучшения

- **Интеграция с AD** — автоматическое создание пользователей при входе
- **Мобильная версия** — адаптивный интерфейс для смартфонов
- **SLA** — автоматическое определение времени обработки
- **Уведомления** — email + push (через веб-пуши)
- **Отчёты** — ежедневные/еженедельные с графиками

### Метрики успеха

- Время обработки заявки сокращено на 30%
- 95% заявок закрыты в срок (SLA)
- Удовлетворённость пользователей ≥ 4.5/5
